# Процесс TDR в команде Learn (draft)

## About

> Процесс в стадии внедрения и нуждается в обратной связи.
Не бойтесь вносить изменения и дорабатывать шаблон/процесс в рамках своей задачи по проектированию TDR.

## Approve

* Аппрувер ожидает от 3+ человек `CR: OK` и завершение всех дискуссий в ревью

## Приоритет CR

* TDR Задачи рецензируются в первую очередь (кроме блокеров)

## Именование

* Каждая TDR должна называться в формате по примеру: `TDR-0001 Awards`

## Процесс

* Для первых TDR каждый ревьювер оставит предложения по улучшению процесса асинхронной защиты. Проследит аппрувер
* Очная встреча для защиты остается, т.к. весьма полезна. В какой момент её лучше организовывать в будущем предстоит
  определить
* Изменения в технический дизайн в рамках реализации следует актуализировать с проектом TDR
    * Ревью проводит аппрувер в новой задаче. Изменения вносятся в оригинальный TDR
    * На усмотрение аппрувера/разработчика можно организовать полный цикл ревью повторно
